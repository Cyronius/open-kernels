# Lessons from the Inkling 2 Mini port

Use these findings to plan model bring-up and choose the first measurements. The [production-bar plan](../plans/inkling2-mini-production-bar.md) records the model-specific evidence, artifact hashes, and remaining checks. The development timings here are from the Windows Ryzen AI 9 HX PRO 370 machine with Phlegm and XRT.

## Pin the inputs and the reference before writing kernels

- Read the publisher config, GGUF headers, and reference runtime together. Record the exact weight file, tensor type counts, tokenizer and chat template, and reference revision. A filename or nominal quant can hide mixed tensor types. Inkling's ggml-org IQ4_NL file uses IQ4_NL and Q8_0 expert tensors. The inspected Unsloth mainline files retain NVFP4 expert tensors. Checking headers first identifies the formats the loader and both block and singleton kernels actually have to support. [Model and reference evidence](../plans/inkling2-mini-production-bar.md#reference-evidence-2026-11-22)
- Check storage and memory for the independent reference up front, including its logit tape. Recheck free space at download time and verify the model size and SHA-256 before publishing the resumable download. Free space for Inkling's 52.2 GB BF16 GGUF fell from 74.6 GB to 44.1 GB over a few minutes. Compare identical token IDs and cache precision first, then use full logits, top-choice margins, and held-out prompts to explain disagreements. At position 522, Phlegm and llama.cpp CPU agreed while Vulkan selected a nearby alternative. The ARC sample matched all 48 Phlegm NPU and CPU answer choices. [Quant comparison](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- On a tight Windows volume, sample transparent compression across the source and measure allocated bytes. Inkling's BF16 samples used 75–87.5% of their original space. Its completed logit tape reclaimed 1.58 GB with an unchanged checksum. Download in verified ranges with a free-space reserve so a competing run can keep its paging headroom. [Reference storage evidence](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- Allow the full-precision weights to live on a separate volume. Capture and verify the baseline logit tape while those weights are available, then compare the candidate quants in a separate run. Pin the reference executable and libraries, fixture token IDs, tape length, and tape hash before reusing a saved result. [Split BF16 evaluation](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- A pinned partial download can support a tensor-level quant comparison. Use complete rows within the downloaded range, validate their offsets and layout with an independent decoder, and include external expert scales. Inkling's sampled Unsloth NVFP4 expert projections were closer to BF16 than Q8_0 or IQ4_NL. Those projection samples leave model-level quality open. [Sampled BF16 expert comparison](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- For a short independent BF16 smoke on a storage-constrained machine, let the reference router choose experts and fetch only the selected tensor ranges. Pin the complete remote object revision, verify each range and length, and hash the bytes you read. Bound the cache and retain separate evidence for the full quality sweep. [Range-backed BF16 fixture](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- Apply each scale where the reference graph uses it. NVFP4's 16-value block scale belongs to weight decoding. The Unsloth file's separate expert scale multiplies the gate/up projection before the activation and the down projection before routed accumulation. Keep those scales with the physical weights and check a trace through every loop pass. [Native NVFP4 comparison](../plans/inkling2-mini-production-bar.md#candidate-quant-comparison)
- Check whether prefill and decode can share one packed weight pool while keeping their current arithmetic. The grouped Q8 prototype read the high limb from the singleton's split-scale layout and reproduced the standard prefill output bytes. The second limb stayed available for decode. Validate both kernel strides and any resume or speculative path before replacing either pool. [Shared Q8 evidence](../plans/inkling2-mini-production-bar.md#dense-q8-block-prefill)
- Write down the chronological visits and their state ownership. Inkling has 24 physical layers and 48 visits. Each visit owns its KV cache and causal convolution state. Validate tap indices and state at the first wrapped window before optimizing. Weight sharing across visits saves weight storage and leaves each visit with its own state. [Runtime contract](../plans/inkling2-mini-production-bar.md#runtime-contract-from-the-reference)

## Budget long context while bringing up short context

- Count transfers and launches from the actual block schedule before booking the board. At the 1,048,449-token fixture, the v11 attention schedule counts about 70 million launches and 1.44 PB of device K/V reads including padding. That is a schedule census. It explains why the 32 GiB-class KV capacity alone cannot predict feasibility. Use a measured stage cost and track all other stages separately. [Schedule census and tier experiments](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Test the full request path early with a cheap transport probe and a real shorter recall. Record rendered token count, batch size, per-bridge-request timeout, HTTP deadline, committed position, and memory. A first 8K Phlegm recall hit the default 600-second bridge request timeout. Splitting prefill into acknowledged chunks made progress observable. A 1M storage replay, a successful tokenizer/HTTP probe, and a 1M attention operator result cover three components. End-to-end 1M inference still needs its own measured recall. [Long-context evidence](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- For overnight Windows runs, hold a scoped idle-sleep request on AC and retain the power and PCI events between the request timestamps. Inkling's 131K midpoint answered correctly, but its 13 hours of wall time included two standby-correlated telemetry gaps totaling 8 h 13 min. Windows also logged a standby entry during a guarded retry that kept committing tokens. Correlate events with the bridge's CPU time and commit trace to measure the interruption. Record the first full-prompt commit separately from the response and use an uninterrupted run for the prefill benchmark. [131K power audit](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- For a costly end-to-end run, keep a known route available and decide between it and the candidate from shorter pairs. Check parity around the cutoff, then measure several full blocks that use the largest tier. Inkling's first 16K-tier fixture reached that tier only in a 33-row tail. The longer fixture times four complete 256-query blocks and retains full-prefix time separately. Keep bridge, manifest and token-ID hashes with the results. Give a missing comparison one fresh attempt and keep both captures. Record the selected route and bundle before the full request, then keep its timing and commit trace. [Long-context evidence](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- When cache updates are already transactional, time both kernel routes on the same committed prefix and discard their tentative state. Check that the later append reproduces the control preview. Keep an independent full-prefix run per route for terminal logits. This cut Inkling's 18K comparison by 44% in evaluated prefill rows before warm-up. [Prefill preview evidence](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Run the longest available intermediate recall with the proposed full-context bundle. Check the exact answer and the per-visit dispatch trace against the expected schedule before carrying that bundle forward. Pin its binaries and trace to the successful run so later rebuilds force a fresh decision. [Long-context handoff](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Estimate full-context runtime from measured stages and their own work counts. Use both a full intermediate trace and its last quarter to show sensitivity to context. Inkling scales older-key dispatch separately by launches and by K/V bytes, and reports those as planning scenarios. [Full-context estimate](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Use the actual mix of tiers when extrapolating from operator timings. At 1M in Inkling, 8.24 million paired 16K dispatches account for 98.8% of older-key K/V bytes. The measured copying control projects roughly 70 hours of dispatch by itself. A short-prompt speed improvement can still leave the full-context run impractical. [Dispatch-only estimate](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Separate the effect of K/V reuse from the precision of a borrowed kernel. A 512-query flash tile reused Inkling's old-key cache at 7.53 TFLOP/s in a repeated operator fixture. Its relative L2 error was 0.02345 against FP64, above the 0.0005 target. Single-BF16 query and output rounding alone also exceeded the threshold. A wide route needs to carry the split query and FP32 partial state through the test. [Wide-query experiment](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Count cache bytes by where they move. The wide Inkling route packs each key group once on the host, then sends it to three query heads. Its 1M schedule would pack 69.9 TB on the host, stream 209.8 TB of old K/V on the device, and read back 3.50 TB of partial state. Include the final partial block and keep dispatch estimates separate from measured Phlegm prefill. [Wide-route census](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Use rollback previews to compare attention variants on the same committed cache. Confirm which tier ran at every full-attention visit. Follow a passing preview with an HTTP recall test that commits the candidate's cache and reaches its widest tier. Use the normal adapter for HTTP validation because Phlegm verifies the adapter hash. [Wide-route measurements](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Measure native packing against the size of a device-side gain. The split BFP16 QK operator saved 9.595 ms at 16K with prepacked keys. Encoding those keys from the runtime layout took 12.882 ms with six host threads, while encoding each 256-row append took 0.221 ms. Check cache memory, rollback and reset before adopting a persistent representation. [QK packing measurement](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Budget simultaneous raw and packed cache storage at maximum context. The experimental Inkling route can retain 18 GiB of packed older keys alongside 32 GiB of raw full-attention K/V. It drops packed keys when singleton decode starts and falls back before altering the attention state if the host packing allocation fails. [Cache memory measurements](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Check how much of a real prompt an optimized path covers. Across seven 256-token blocks of the 32K HTTP recall request, wide older-key attention used 5.37% of block time and MoE used 39.5%. Pair the actual prompt length with the timing and report smaller stage gains separately. [Phlegm trace](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Count aligned chunks using the full query group. A 1,024-token sliding window can require 33 chunks of 32 keys for a 16-query group. The resulting choice of a 64-chunk tier nearly doubles transferred bytes. Re-lower the deployed IR for an intermediate tier and compare the binaries before running parity and timing checks. [Sliding attention tier](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Use the measured operator comparison to choose which real model run to book. Bind that choice to the complete bundle because two attention images can share the same manifest bytes. Keep the model-level timing and logits check for whichever image advances. [Direct-DMA evaluation](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- For a softmax shortcut, count how often the running maximum changes at the kernel's actual tile size. Preserve the rounding of the previous accumulator even when the rescale factor is one. Check both paths on device and bracket their timings with the original kernel. [Older-key rescale experiment](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- When online attention fails, inspect peak, mass, and numerator separately. In Inkling's combined matrix path, 332 archived peaks matched valid scores, all in the final chunk. Retest with one, two, and four visible chunks and toggle scoring and value accumulation independently in the same compiled image. [Matrix attention isolation](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- If the host reconstruction passes and device state is wrong, trace the compiled load addresses back to the placed buffers. In Inkling's combined matrix kernel, Peano folded the previous peak load into a post-increment read from the numerator. Simulate the observed address against the faulty device result, then verify the new address in the rebuilt image before rerunning device quality. [Matrix attention load audit](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- When shortening an exponential approximation, preserve the exact value at zero and evaluate the full range reduction with the kernel's precision. Check normalized attention against FP64, then repeat on hardware and verify full model logits before using the approximation in a release route. [Older-key exponential experiment](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- When reusing a key tile across query groups, distinguish core-local loads from off-core DMA. Inkling's paired score build keeps the same K/V DMA span and adds a second score buffer. Check linked data placement and the sum of nested stack frames before spending device time on the comparison. [Paired-key build](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Check a proposed precision change before compiling it. Dropping Inkling's low BF16 query term exceeded the old-key accuracy limit on every head and query-group pair in the 16K fixture, even with FP64 attention and the original K/V. [Query precision check](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Run each expensive needle depth in a fresh process. Keep the partial committed position and HTTP error if a case fails, then retain the other depths' results independently. A 131K retry timed out before its first recorded commit and prevented the next depth from starting in the original grouped invocation. [Long-context evidence](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- On a shared NPU, run the short probes and the model comparison that decide the next long recall before feature checks with long timeouts. Keep independent receipts so a failed check leaves the other evidence intact. Recheck the selected bundle after the feature slot before starting the long recall. [Phlegm acceptance queue](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Count padding at the actual positions served. In the 512-token decode trace, the runtime selected a 32-chunk stream when 17 chunks sufficed. The wire calculation drops K/V traffic from 8.05 GB to 4.28 GB over 32 forced steps with the same launch count. The alternate streams passed compiler and manifest checks. Their measured impact still depends on the on-device comparison. [Attention profile and finer tier](../plans/inkling2-mini-production-bar.md#host-projections)

## Measure the whole route and keep the comparisons small

- Measure ordinary block prefill before spending the device on maximum context. Inkling's 8K control ran at about 15 tokens/s. In the retained 512-token trace, grouped experts accounted for 44% of wall time and about 10 seconds remained outside the named host and device stages. Use the saved Phlegm profiler to separate wait, transfers, validation, and host math. [Profiler guide](../../../benchmarks/reference/inkling2-prefill/README.md) [Ordinary prefill evidence](../plans/inkling2-mini-production-bar.md#host-projections)
- Use the measured stage shares to bound the expected end-to-end improvement. Inkling's 512-token trace had 14.35 s outside timed device interfaces, compared with 6.42–7.61 s for the whole Vulkan prefill. Submission savings alone leave substantial host work. Record normalization, cache commit, and the count of CPU attention and head fallbacks alongside the controller update and attention gate. [Profiler guide](../../../benchmarks/reference/inkling2-prefill/README.md) [Host timing evidence](../plans/inkling2-mini-production-bar.md#host-projections)
- Check whether launches overlap host work before tuning individual host stages. Inkling's prefill launches were all synchronous. In the retained 512-token trace, 9.82 of 38.58 seconds was host work inside the expert and dense interfaces with the array idle, and submit and wait across all three device stages totaled 13.37 seconds. Read the engine's existing dispatch requirements first. The block GEMM route already records the one-launch rule, the patch rule, the fenced readback and a measured 19–22% gain. [Launch overlap candidate](../plans/inkling2-mini-production-bar.md#host-projections) [Stage-major prefill](../plans/prefill-pipeline.md)
- Confirm that a session can run builds, scripts and device tools before assigning it work that depends on them. One Inkling handoff session could read and edit files only. It produced a staged candidate with no build or measurement. Label such code as unbuilt in the plan, and keep it out of the engine until its exact-logit comparison has run. [Launch overlap candidate](../plans/inkling2-mini-production-bar.md#host-projections)
- For an overlap change, exercise lane reuse without a device, then verify output bits and wall time on the real stack. Inkling's extracted schedule passed checks for up and down group order, one run in flight and cold staging. All eight device trials matched every final logit and grouped launch count. Their control drift was 5.29%, so the exactness result stood and the timing needed a focused repeat. The repeat used the same binary and put control runs around two trials of the full candidate. Control drift was 3.79%, and prefill fell from 23.17 to 14.11 seconds at 512 tokens. [Launch overlap verification](../plans/inkling2-mini-production-bar.md#host-projections)
- Carry the winning short configuration to a prompt with a partial final block. In one Phlegm pair at 8,225 tokens, the full overlap candidate took 296 seconds against 510 for the control, with identical logits and launches across 32 full blocks and a 33-token tail. Record the short repeat and the single longer pair independently. The longer stage profile still spent 123 seconds in MoE and 92 seconds in relative attention. [Longer overlap comparison](../plans/inkling2-mini-production-bar.md#host-projections)
- Check the precision at the next operator boundary before changing a host activation. Inkling's grouped expert down projection rounds SiTU outputs to BF16 before packing. A vector prototype checks its BF16 rounding interval and sends uncertain lanes to the scalar function. The Phlegm shadow run compared each lane before packing and reproduced the known final logits. The vector pass cut stage time by about 70%, while the full prompt timings shifted by less than the drift between controls. Time only active expert rows in the microbenchmark and follow it with the ordinary pipeline, where SiTU overlaps device work. [Expert activation replay](../plans/inkling2-mini-production-bar.md#host-projections)
- Multiply isolated host savings by the real visit count before booking device time. Parallel Q/K/V postprocessing preserved every tested output bit and cut the stage by as much as 0.45 ms per 256-row visit. Across the retained 512-token fixture that is about 43 ms of possible savings on a 38.58-second request. [Q/K/V timing evidence](../plans/inkling2-mini-production-bar.md#host-projections)
- Time full-output validation separately from device readback. Replaying captured Inkling expert outputs found that a vector exponent check took 15–28 μs per buffer and preserved the scalar decision, including padding and non-finite values. Measure the impact next to the real readback and unpack before crediting it to model throughput. [Validation experiment](../plans/inkling2-mini-production-bar.md#host-projections)
- Measure the total savings from removing repeated work before changing the host/engine interface. Caching gate/up activation packs matched every wire in a 48-visit replay and cut host gather-and-pack time by roughly two thirds. It saved about 45 ms of work for a 256-token prompt in host buffers. [Activation reuse experiment](../plans/inkling2-mini-production-bar.md#host-projections)
- When comparing prefill block sizes, keep the prompt and warm-up token counts equal across arms. Record the bridge's reported block size and the committed spans, then count expert dispatches and compare full logits. Repeating one Inkling router histogram estimated 17.1% fewer expert dispatches with 512-token blocks. Measure the actual router and wall time on the full model. [Profiler guide](../../../benchmarks/reference/inkling2-prefill/README.md) [Block-size experiment](../plans/inkling2-mini-production-bar.md#host-projections)
- Re-measure a block-size change after enabling overlap. On Inkling's synchronous route, 512-token blocks reduced warm time by 8–10% for a 512-token prompt. On the overlapped route at 1,536 tokens they cut launches by 15.3%, matched logits, and showed no consistent gain in wall time. The combined result kept the 256-token default. [Block-size comparison](../plans/inkling2-mini-production-bar.md#host-projections)
- Evaluate expert width at the intended prompt block size. In Inkling's 256-token capture, going from 32 to 48 rows per expert cut launch count and raised aggregate wire bytes slightly. Repeating the routes as a 512-token block reduced both launch count and bytes. Keep the masked padding and real zero-row tests, then measure the actual same-block Phlegm comparison. [Grouped expert experiment](../plans/inkling2-mini-production-bar.md#grouped-expert-prefill)
- Count submission and sync savings separately from physical traffic. Inkling's compiled paired dense stream joins two 64-row waves with the same worker image and repeats the weight DMA. It predicts half the dense calls at 512 tokens with the same weight traffic. Check both output waves, route counters and full-model wall time before selecting it. [Paired dense experiment](../plans/inkling2-mini-production-bar.md#host-projections)
- When pairing grouped expert launches, verify that each wave uses its own weight addresses and preserve the host's expert accumulation order. Two-wave M16 keeps Inkling's current workers and arithmetic. The recorded router histogram predicts 48.8% fewer group submissions with a single-wave tail. [Paired expert experiment](../plans/inkling2-mini-production-bar.md#host-projections)
- Evaluate paired late-block speed before starting a second long prefill for terminal quality. If the candidate already missed the speed threshold in both orders, retain the timing evidence and defer the expensive terminal check unless that result has independent value. [18K qualification](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Use one prompt and forced continuation to compare a warm Phlegm route and an independent backend on the same machine. Attribute time to packing and sync, dispatch and waits, readback, and host projections before changing kernel arithmetic. A 512-token v11 development trace spent 17.14 of 38.58 seconds of prefill in grouped expert interfaces and 14.35 seconds outside measured device interfaces. Tiling the host F32 projections reduced the controller/router portion from about 4.1 seconds to about 1.1–1.2 seconds in both run orders, and the full prefill improvement was smaller. [Host projection measurements](../plans/inkling2-mini-production-bar.md#host-projections)
- Use the Phlegm device lock and bracket changes with warm controls in both orders. Account for compilation or reference inference on the same machine. The wider grouped-expert test passed all 96 numerical comparisons, but its baseline measurements drifted by at least 27.8%. Those captures establish numerical parity. The aborted model replay also showed the value of saving stdout, stderr, and exit status separately at every handoff. Keep raw-operator results and model timings attached to their own evidence. [Grouped expert experiment](../plans/inkling2-mini-production-bar.md#grouped-expert-prefill)
- Inspect individual launches when the first control bracket drifts. In Inkling's paired-key probe, the first control fell from 51.34 to 38.68 ms across eight launches and later controls settled near 29.96 ms. The other two brackets showed about 9.1% gain. Repeat with an explicit warm-up before treating all three brackets as speed evidence. [Older-key board results](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Compare traffic savings with the actual decode cost on the device. Inkling's lossless K/V format used 18.75% fewer wire bytes and reproduced the raw attention output exactly. It took longer at all three measured key counts. A separate streamed host pack improved the pack and sync stage on mapped XRT buffers, with aggregate Phlegm impact still open. [K/V measurements](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Isolate score and value changes in one attention image. The corrected Inkling kernel passed the FP64 and relative fallback checks at 4,096 keys. Packed scoring alone reduced dispatch time by 24–26%, while enabling both packed scoring and packed values reduced it by 5–11%. Carry the faster operator into model tests that include packing and transfers. [Corrected matrix attention evidence](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Use the transfer census to choose which parts of attention to measure. At 131K in Inkling, complete old ranges account for 71% of launches and 82% of device K/V bytes. Run small, bracketed device probes on those ranges before committing another long run. Measure time independently of wire size. [Attention stage and layout probes](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Test host packing against the complete destination, including fields the kernel skips. Inkling's row-major old-range fast path preserved its unused relative stripe and cut isolated packing from about 2.0 to 0.5 ms per 4,096 keys. Compare the real mapped buffer, sync and dispatch before using that ratio as an attention speedup. [Full-attention packing](../plans/inkling2-mini-production-bar.md#full-attention-prefix-reuse)
- Check which image the manifest selects even when a feature flag is off. In the singleton experiment, both flag settings select the shared NPU attention and expert image. Measure the original bundle, the shared image with host projections, and the shared image with NPU projections to attribute any change to the right cause. [Dense attention experiment](../plans/inkling2-mini-production-bar.md#dense-q8-block-prefill)
- Match a CPU projection tile to an actual model batch. DSpark executes eight backbone rows together. Sharing one Q8_0 weight unpack across all eight preserved every captured proposal logit under MSVC and Clang and reduced CPU draft time in the paired replay. Measure the backbone and full draft separately before deciding whether it helps Phlegm throughput. [DSpark verification and timing](../plans/inkling2-mini-production-bar.md#steps)
- When an NPU path spends host time packing activations, verify changes against an independent byte layout for every precision mode. Include saturation, rounding modes, partial tiles, and the portable build. Inkling's AVX2 pack reduced the measured tile conversion time by an order of magnitude. Use the paired Phlegm run to measure the effect on the whole request. [Activation pack evidence](../plans/inkling2-mini-production-bar.md#host-projections)
- Keep the kernel writer and manifest reader tied to the same bundle, and verify both ends after a change. When adding a tier to an existing image, reproduce the deployed control instruction streams and check exactly which worker settings and DMA spans change. Save weight, fixture, bundle, bridge, and source hashes in a small summary linked from the plan. Put bulky captures and generated files under `.plans/`. [Engine and kernel contract](../../../AGENTS.md#direction)
- Capture each stream's compiler settings in one exporter as soon as the bundle combines several designs. Keep packaging separately runnable so it can be checked against captured compiler outputs while a fresh source build runs. Inkling's 40 streams packaged into 49 files, all byte-identical to the tested v11 bundle. Use a staging directory so a failed pack leaves no partial bundle at the requested output path. [Rebuild the v11 kernel bundle](../plans/inkling2-mini-production-bar.md#rebuild-the-v11-kernel-bundle)
- When fresh builds produce different XCLBIN hashes, compare the instructions, core ELFs, initialization, and XRT sections. Inkling matched all of those compiled streams and initialization binaries, and its embedded programming images matched from byte 256 onward. The newly built containers still need their own Phlegm smoke. [Source rebuild evidence](../plans/inkling2-mini-production-bar.md#rebuild-the-v11-kernel-bundle)

## Exercise release entry points and features early

- Verify the normal Phlegm model directory has the pinned target GGUF and the required sidecars before booking hardware. Confirm what the bridge advertises after initialization. For DSpark, compare plain and speculative output at the sliding-window boundary, force partial acceptance to check rollback, and measure accepted proposals and throughput together. Short development tests showed a throughput gain on one workload and a loss on another. Use ordinary JSON and streamed requests for reasoning, tool calls, and vision, including their combinations with speculation. [Production gates](../plans/inkling2-mini-production-bar.md#production-bar)
- Use the real GGUF tokenizer with scripted reply tokens to exercise HTTP framing while the NPU is busy. For multiple tool calls, return results in reverse order and verify the rendered template pairs each result with its call ID. Inkling's replay covered two tool calls in both JSON and SSE, including Unicode and a literal protocol marker inside an argument. Keep a separate live-model check for generated calls. [Phlegm text integration](../plans/inkling2-mini-production-bar.md#phlegm-text-integration)
- Exercise each intentionally invalid bridge command in its own process. The Phlegm reference bridge sends an error reply and exits on invalid requests. Mixing such requests into Inkling's valid DSpark rollback matrix stopped the suite early. [DSpark verification](../plans/inkling2-mini-production-bar.md#steps)
- Save each HTTP fixture and response before advancing a paired suite. Keep a case filter that preserves the original capacity and request so a large failing case can be isolated on a fresh server. After the 1,792-pixel DSpark timeout, fresh servers matched the plain-decode responses for the 1,792- and 4,096-pixel fixtures. The 4,096-pixel run recorded a Modern Standby entry despite the scoped wake request, so its response qualifies as functional evidence and its timing is excluded from speed claims. [Phlegm image QA](../plans/inkling2-mini-production-bar.md#steps)
- For timed Windows prefill, retain the profiler's `power_status` and the scoped event log. The runner records which wake requests Windows accepted and samples AC or battery power and battery saver at both ends. Use the event log to identify standby transitions during the run. [Profiler output](../../../benchmarks/reference/inkling2-prefill/README.md#read-the-result)
- Check speculative rollback and direct-decode parity separately. Changing the rejected suffix in 18 Phlegm NPU cases preserved all scored and committed state outputs. A direct-decode comparison still changed the first subsequent top token in one sliding-window case. Compare draft-path scores along their common input prefix and record the first diverging token and both logit gaps. For stage attribution, replay the same committed state before each arm and compare full-block acceptance, a kept-only block, and singleton execution. [DSpark rollback evidence](../plans/inkling2-mini-production-bar.md#steps)
- Match archived prelude logits when investigating a later speculative mismatch. Inkling's two original captures already differed at position 1,032. Recreate both starting states using the original bridge calls, including draft proposals that were rejected, and compare every new verification arm from each state. [DSpark replay evidence](../plans/inkling2-mini-production-bar.md#steps)
- Trace projection inputs and outputs before changing a verifier's cache logic.
